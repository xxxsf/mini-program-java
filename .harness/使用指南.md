## 配置连接器

连接器是 Harness 与外部服务通信的桥梁。

### 1. 配置 GitHub 连接器

**步骤：**
1. 在 Harness 项目中，进入 **Connectors**
2. 点击 **New Connector**
3. 选择 **Code Repositories** → **GitHub**
4. 填写配置：
   ```
   Name: github-connector
   Description: Connect to GitHub repository
   Connection Type: HTTP
   GitHub Account Type: Personal
   URL Type: Account
   ```
5. 点击 **Continue**
6. 配置认证：
   - 选择 **GitHub App** 或 **Personal Access Token**
   - 如果使用 Token，在 GitHub 创建 Token (repo 权限)
7. 点击 **Connect** 测试连接
8. 保存连接器

**记录连接器 ID：** `account.github-connector` 或类似标识

### 2. 配置 Docker Registry 连接器

**Docker Hub 示例：**
1. 进入 **Connectors** → **New Connector**
2. 选择 **Artifact Registries** → **Docker Registry**
3. 填写配置：
   ```
   Name: docker-hub-connector
   Docker Registry URL: https://hub.docker.com
   Provider: Docker Hub
   ```
4. 配置认证：
   - 用户名：您的 Docker Hub 用户名
   - 密码：Docker Hub 访问令牌 (不是登录密码)
5. 测试连接并保存

**AWS ECR 示例：**
1. 选择 **Amazon Elastic Container Registry**
2. 配置 AWS 凭证和区域
3. 测试连接

**记录连接器 ID：** `account.docker-hub-connector`

### 3. 配置 Kubernetes 连接器

**步骤：**
1. 进入 **Connectors** → **New Connector**
2. 选择 **Cloud Providers** → **Kubernetes Cluster**
3. 选择认证方式：

**方式 A: 使用 Kubeconfig**
```
Name: kubernetes-connector
Authentication: Delegate Kubernetes credentials
```

**方式 B: 使用服务账号**
```
Name: kubernetes-connector
Authentication: Service Account
```

4. 上传您的 kubeconfig 文件或配置服务账号
5. 测试连接并保存

**记录连接器 ID：** `account.kubernetes-connector`

## 导入管道配置

### 选项 1: 从 Git 导入 (推荐)

1. 在项目中，进入 **Pipelines**
2. 点击 **Create Pipeline**
3. 选择 **Import from Git Repository**
4. 选择您的 GitHub 连接器
5. 选择仓库：`mini-program-java`
6. 选择分支：`main`
7. 文件路径：`.harness/pipeline.yaml` (或其他配置文件)
8. 点击 **Import**

### 选项 2: 手动创建

1. 点击 **Create Pipeline**
2. 选择 **Blank Pipeline**
3. 管道名称：`invoice-tool-pipeline`
4. 点击 **Start**
5. 在 YAML 编辑器中，复制 `.harness/pipeline.yaml` 的内容
6. 根据您的连接器 ID 更新配置：
   ```yaml
   # 更新这些引用
   connectorRef: account.github-connector  # 您的 GitHub 连接器
   connectorRef: account.docker-hub-connector  # 您的 Docker 连接器
   connectorRef: account.kubernetes-connector  # 您的 K8s 连接器
   ```

### 更新配置文件中的连接器引用

编辑导入的管道配置，更新连接器引用：

```yaml
# 在 Build stage 中
cloneCodebase:
  connectorRef: account.github-connector  # 更新为您的连接器 ID
  repoName: mini-program-java

# 在 Docker build 步骤中
imagePath: your-dockerhub-username/invoicetool:latest  # 更新为您的 Docker 镜像路径

# 在 Deploy stage 中
connectorRef: account.kubernetes-connector  # 更新为您的 K8s 连接器
```

## 运行管道

### 1. 首次运行

**步骤：**
1. 进入 **Pipelines**
2. 选择 `invoice-tool-pipeline`
3. 点击 **Run**
4. 配置运行参数：
   ```
   Branch: main
   # 其他参数根据需要填写
   ```
5. 点击 **Run Pipeline**

### 2. 监控执行过程

管道执行分为几个阶段：

**Build Stage:**
- ✅ Clone Codebase - 克隆代码
- ✅ Setup Java - 设置 Java 环境
- ✅ Maven Build - Maven 构建
- ✅ Run Tests - 运行测试
- ✅ Build Docker Image - 构建 Docker 镜像

**Deploy Stage:**
- ✅ Rolling Deployment - 滚动部署

### 3. 查看日志

- 点击每个步骤可以查看详细日志
- 如果某个步骤失败，点击失败的步骤查看错误信息
- 日志可以下载用于分析

## 配置密钥和敏感信息

### 1. 在 Harness 中创建 Secrets

**步骤：**
1. 进入项目中的 **Secrets**
2. 点击 **New Secret**
3. 选择 **Text Secret**
4. 创建数据库密码：
   ```
   Name: mysql_password
   Value: your_actual_password
   ```

5. 创建 Docker Registry 密码：
   ```
   Name: docker_hub_password
   Value: your_docker_token
   ```

### 2. 在管道中使用 Secrets

更新管道配置，引用这些 Secrets：

```yaml
# 在环境变量中引用
- name: SPRING_DATASOURCE_PASSWORD
  value: <+secrets.getValue("mysql_password")>
```

## Kubernetes 部署配置

### 1. 更新 Kubernetes 清单文件

编辑 `.harness/k8s/configmap.yaml`：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: invoicetool-config
data:
  spring.datasource.url: "jdbc:mysql://your-mysql-service:3306/invoicetool?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true"
```

### 2. 更新 Secret 文件

编辑 `.harness/k8s/secret.yaml`：

```bash
# 编码您的凭据
echo -n "your_db_username" | base64
echo -n "your_db_password" | base64
```

然后更新 secret.yaml 中的值。

## 常见使用场景

### 场景 1: 开发环境自动部署

```yaml
# 修改 pipeline.yaml，在每次 push 到 dev 分支时自动触发
trigger:
  name: dev-push-trigger
  identifier: dev-push-trigger
  enabled: true
  stagesToExecute:
    - Build
  conditions:
    - type: Webhook
      spec:
        type: GitHub
      spec:
        header:
          - key: X-GitHub-Event
            value: push
        body:
          - key: ref
            value: refs/heads/dev
```

### 场景 2: 生产环境手动审批

```yaml
# 在 Deploy stage 前添加审批步骤
- stage:
    name: Approval
    identifier: approval
    type: Approval
    spec:
      execution:
        steps:
          - step:
              type: HarnessApproval
              name: Manual Approval
              identifier: manual_approval
              spec:
                approvalMessage: "Please approve the deployment to production"
                includePipelineExecutionHistory: true
                approvers:
                  userGroups:
                    - production-approvers
```

## 监控和故障排除

### 1. 查看执行历史

- 进入 **Pipelines** → 选择管道 → **Executions**
- 查看所有历史执行记录
- 比较不同执行的差异

### 2. 常见问题

**问题 1: 构建失败 - Maven 依赖下载**
```
解决方案：
- 检查网络连接
- 增加构建超时时间
- 使用 Maven 依赖缓存
```

**问题 2: Docker 推送失败**
```
解决方案：
- 验证 Docker Registry 凭证
- 检查镜像名称格式
- 确认仓库权限
```

**问题 3: Kubernetes 部署失败**
```
解决方案：
- 检查 kubeconfig 配置
- 验证集群连接性
- 查看 Pod 日志：kubectl logs -f deployment/invoicetool
- 检查资源配额
```

**问题 4: 数据库连接失败**
```
解决方案：
- 验证数据库地址和端口
- 检查网络策略
- 确认凭据正确性
- 测试数据库可访问性
```

### 3. 设置通知

**配置 Slack 通知：**
1. 在 Project Settings 中配置 Slack 连接器
2. 在管道中添加通知步骤：
```yaml
notifications:
  - type: Slack
    spec:
      webhookUrl: <+secrets.getValue("slack_webhook")>
      message: "Pipeline ${pipeline.name} execution ${pipeline.status}"
```
